Counter-before-hash on the secp160k1 top byte (HANDOFF §4.2(b))
======================================================================
  secp160k1  top nibble (bits156-159)=4  high=0x0  low152 core=8ce563f89a0ed9414f5aa28ad0d96d6795f9c6
  secp192k1  top nibble (bits156-159)=7  high=0x554123b  low152 core=8ce563f89a0ed9414f5aa28ad0d96d6795f9c6
  secp224k1  top nibble (bits156-159)=7  high=0x3b  low152 core=8ce563f89a0ed9414f5aa28ad0d96d6795f9c6
  secp256k1  top nibble (bits156-159)=7  high=0x3b  low152 core=8ce563f89a0ed9414f5aa28ad0d96d6795f9c6

A. Heuristic argument: the top nibble is unlikely to be hash output
   All four share bits 4..155 (152 bits). The differing part the name calls
   the 'top byte' is really the nibble at bits 156..159: 0x4 on secp160k1,
   0x7 on the other three (bits 152..155 = 0x8 are shared, inside the core).
   Let value_k = HASH(input_k) for curve k, input_k = seed with a counter
   folded in (any encoding above). Projection onto 152 bits is many-to-one,
   so equal projections do NOT prove equal inputs. But under an
   independent-hash heuristic two different inputs agree on bits 4..155 with
   probability ~2^-152 per pair, so with overwhelming likelihood the four
   share one hashed input -- and one input gives one output everywhere,
   including bits 156..159, which are 4 vs 7. The likely reading: the
   differing nibble is a post-hash edit, and a counter in the input, if there
   was one, produced only the shared digest. This is a probabilistic
   heuristic, not a proof, and it is separate from the bounded probe in C.

A'. Illustration (a sample, not an impossibility result)
    The observed signature is a PAIR of curves whose low 152 bits (bits 4..155)
    are equal WHILE the top nibble (bits 156..159) differs. Model: for each
    curve, i = 0,1,2,... ; D = SHA1(seed || i_be4); accept the first D that
    lifts to a point. The two outcomes seen are: curves land on the same i
    (identical FULL digest, top nibble included), or on different i
    (independent digests). Count signature pairs across seeds.
    64 seeds, 384 curve-pairs examined.
    pairs matching the observed signature (shared 152-bit core, DIFFERENT top
    nibble) = 0.  (The real data shows it on 3 of 6 pairs:
    secp160k1 against each of the other three; the pairs among 192/224/256
    share the top nibble 7 as well as the core, so they are not the signature.)
    => in this sample, counter-before-hash yields either an identical digest
       (same top nibble too) or an independent one. A sample of 64 seeds
       illustrates the heuristic in A; it does not rule the signature out.

B. If the edit is itself a counter/tag, does one rule fit all four?
    secp160k1  field 160 bits, tag above bit156 = 0x4
    secp192k1  field 192 bits, tag above bit156 = 0x554123b7
    secp224k1  field 224 bits, tag above bit156 = 0x3b7
    secp256k1  field 256 bits, tag above bit156 = 0x3b7
    secp224k1 and secp256k1: identical tag 0x3b7 over DIFFERENT fields;
    secp192k1: 0x554123b7, the LARGEST tag over the SMALLEST of the three
    extended fields; secp160k1: 0x4, no high material. No monotone function
    of the field size produces this set, and 224 = 256 disfavours a
    free-running per-curve counter. Not excluded: a counter restarted for
    each run, or buffer state reused between runs, either of which repeats.
    The tag tracks which curves reuse a value, not the field -- consistent
    with a hand-written limb, which stays the working hypothesis.

C. Bounded probe: counter folded into the input, matched against the core
    21,316,608 evaluations over 6939 base strings, counter 0..127, 2 encodings, 6 placements, 2 hashes: 0 hit(s).
    manifest -> results/counter-before-hash-probe.json

CONCLUSION
  Counter-before-hash as the SOURCE OF THE TOP BYTE is disfavoured, not
  disproved: under the independent-hash heuristic the shared 152-bit core
  points to a single hashed input, which would give one top nibble, so the
  0x78->0x48 edit on secp160k1 (and the 0x3b / 0x554123b high material) most
  likely happened after the hash -- consistent with the §7.3.7 working
  hypothesis of hand-assigned tags, which this does not establish. A counter
  in the input could still explain the shared digest itself. Separately,
  the bounded probe below is a negative over its stated domain only.
  Untested here: a counter before a SECOND hash or transform of the digest
  (modelled next, counter_second_hash.py) and any input outside the probe.
  The bounded input-counter probe: 21,316,608 evaluations over 6939 Certicom base strings, counter 0..127, 2 encodings, 6 placements, hashes ['sha1', 'ripemd160']: 0 hit(s) on the core.
